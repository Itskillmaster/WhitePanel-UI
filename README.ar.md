## ✦ لماذا WhitePanel؟

معظم بنى البروكسي مزيج من سكربتات نصف مترابطة: واحد للمستخدمين، وآخر للاشتراكات، وثالث للبوت، والباقي في ملف نصي.

**WhitePanel** يجمع كل ذلك في **سطح تشغيل واحد** — ويعمل سواء على VPS مباشرة أو في بيئة حاويات لا يُعرف اسم النطاق العام فيها إلا *بعد* النشر.

<div align="center" dir="ltr">
  <img src="svg/features.svg" alt="WhitePanel features" width="100%" />
</div>

### القدرات الأساسية

| المجال | ما يقدّمه لك |
|---|---|
| 👤 **المستخدمون** | إنشاء وإدارة الحسابات والحدود والحركة والروابط والإجراءات |
| 🔗 **الاشتراكات** | صفحات الاشتراك، روابط الإعدادات، رموز QR والنسخ السريع |
| 🛰 **العقد** | إدارة العقد، فحص الصحة، التحديث والمزامنة |
| 🧪 **الماسح** | أدوات TCP / IP / SNI وقوائم نتائج سهلة النسخ |
| 🤖 **بوت تيليغرام** | إعداد البوت وأتمتة القنوات ومسارات المبيعات |
| 🛒 **بوت البيع** | الباقات والإيصالات والموافقة اليدوية وتسليم الاشتراك |
| 🟢 **الانتهاء** | معالجة انتهاء الصلاحية وتنظيف المنتهية تلقائياً |
| 🛠 **الأدوات** | معلومات التشغيل والعاملون وحالة النفق ونقاط مساعدة |

> **منفذ اللوحة الثابت: `8080`.** احفظه مرة واحدة ولا تبحث عنه مجدداً.

## الخيار A — تثبيت بأمر واحد على VPS

شغّل المثبّت على VPS لينكس مدعوم:

```bash
bash start.sh install
```

يتولّى المثبّت تجهيز التبعيات وملفات التطبيق وإدارة التشغيل. وتستمع اللوحة على **منفذ `8080`**.

### متغيّرات المثبّت المفيدة

| المتغيّر | الافتراضي | الغرض |
|---|---|---|
| `WHITE_APP_DIR` | `/opt/WhitePanel` | دليل التطبيق |
| `WHITE_REPO` | *(غير محدّد)* | مستودع Git للنشر |
| `WHITE_BRANCH` | `main` | الفرع المنشور |
| `WHITE_INSTALLER_URL` | رابط `start.sh` الخاص بالمشروع | مصدر المثبّت |
| `WHITE_UV_VERSION` | `0.12.9` | إصدار uv المستخدم |
| `WHITE_XRAY_VERSION` | `26.3.27` | إصدار Xray المستخدم |

```bash
# نشر فرع معيّن في دليل مخصّص
WHITE_APP_DIR=/opt/WhitePanel WHITE_BRANCH=main bash start.sh install
```

> 🔒 لا تضع الأسرار داخل المستودع؛ استخدم متغيّرات البيئة أو إعدادات خادم محمية.

## الخيار B — Railway

1. انسخ المستودع إلى حساب GitHub الخاص بك.
2. أنشئ مشروعاً جديداً في Railway من المستودع.
3. دع Railway يبني باستخدام `Dockerfile` و`railway.toml`.
4. اجعل التطبيق يستمع على **المنفذ `8080`**.
5. أنشئ نطاقاً عاماً.
6. افتح النطاق المُنشئ وادخل إلى اللوحة.

### ملاحظات Railway

- عملية التطبيق تستمع على `0.0.0.0:8080`.
- يستخدم `railway.toml` نفس المنفذ الثابت مع Uvicorn.
- اكتشاف النطاق العام مهم: روابط الاشتراك تُبنى منه.
- لا تستخدم `localhost` كنطاق اشتراك عام.

# 🧭 النقطة العامة وتدفق الاشتراك

يحتوي WhitePanel على أدوات لنقطة النهاية العامة حتى تعمل اللوحة عندما يُحدَّد النطاق النهائي *بعد* النشر.

```text
Panel
  ├─ /white                → اللوحة الرئيسية
  ├─ /login                → صفحة الدخول
  ├─ /dashboard            → لوحة المعلومات
  ├─ /link/<uuid>          → صفحة رابط المستخدم
  ├─ /p/<uuid_key>         → صفحة الاشتراك العامة
  └─ /api/sub/<uuid_key>   → نقطة نهاية الاشتراك
```

توجد أيضاً نقاط نهاية لرموز QR لتسليم إعدادات الاشتراك/المستخدم.

# 🤖 أتمتة تيليغرام

يوفّر WhitePanel مسارات تخص تيليغرام للإدارة وعمليات القنوات والمبيعات.

### بوت القناة

يستطيع مسار بوت القناة إنشاء مستخدم جديد، وتوليد الاشتراك ورمز QR، ونشر المحتوى في القناة المحدّدة، ثم تنفيذ خطوة التنظيف بعد التسليم الناجح.

### بوت البيع

مسار العميل بسيط عن قصد — البساطة تعني مبيعات:

```text
🟢 حسابي   →   🛍 المنتجات   →   💬 الدعم
```

كل باقة تُدار بشكل مستقل ولها اسمها وسعرها ودخلها وحصتها ومدةها وبادئة المستخدمين.

مسار الشراء النموذجي:

```text
/start
   ↓
🛍 المنتجات
   ↓
اختيار الباقة
   ↓
معلومات الدفع
   ↓
رفع الإيصال
   ↓
مراجعة المشرف
   ├─ ✅ قبول → اشتراك + QR
   └─ ❌ رفض
```

كما يُدعم فرض عضوية القناة، ومعرّفات المشرفين الرقمية، وإدارة الباقات، ومعالجة الانتهاء.

---

# 🛡 الحساب والصلاحية والتسليم

### هوية الحساب

يربط مسار البيع كل عميل بـ **معرّف تيليغرام الرقمي**. تُحدَّث الحسابات الموجودة بدل تكرارها، وصُمّمت تفعيل الطلبات لتجنّب تطبيق عملية شراء مرتين.

### انتهاء الصلاحية

عند بلوغ تاريخ انتهاء المستخدم، يحاول sweeper حذف الحساب وتنظيف ربط تيليغرام ثم إبلاغ المستخدم بالانتهاء.

### أمان التسليم

التفعيل والتسليم منفصلان عمداً، بحيث لا يعني فشل تسليم مؤقت في تيليغرام أن الحساب تكرّر أو أن حساباً سابقاً أُبلغ بأنه حُذف خطأً.

# 🔎 الماسح

يتضمّن قسم الماسح أدوات حول:

- فحوصات TCP / IP
- بيانات شبكات Cloudflare الفرعية
- قوائم وفحوصات SNI
- معالجة نتائج فحص IP/SNI
- عمليات ping مجمّعة
- أدوات أسرع نتيجة

الواجهة على الجوال مضغوطة وصديقة لللمس حتى يُنسخ النطاق أو IP بلمسة مباشرة.

# ⚙️ التشغيل وواجهة API

الخلفية مبنية على **FastAPI / Uvicorn** وتحتوي نقاط نهاية للمصادقة والمستخدمين والاشتراكات والعقد والماسحين والعاملين وإعدادات بوت تيليغرام ومعلومات التشغيل.

يفتح صورة Docker اللوحة على:

```text
0.0.0.0:8080
```

لنشر نظيف، اربط اسم النطاق العام بمنفذ التطبيق هذا.

---

# 🎨 تفاصيل الواجهة

تستند الواجهة إلى:

- عرض داكن/فاتح متجاوع — أساس أسود خالص ولمسة فيروزية `#00e1c1`
- تفاعلات مضغوطة صديقة للمس
- إجراءات نسخ سهلة لإعدادات الاتصال
- أقسام قابلة للطي
- صفحات اشتراك مع تسليم QR
- تدفقات بأسلوب أزرار زجاجية في تيليغرام
- تخطيط سطح المكتب + الجوال

مجلّد `svg/` يحوي الرسوم الأصلية للمستندات؛ وهي ملفات SVG مستقلة للحفاظ على الهوية البصرية دون لقطات نقطية — وألوانها مطابقة لمظهر اللوحة الفعلي.

---

# 🔐 ملاحظات الأمان

- لا ترفع رموز البوت وكلمات المرور ومفاتيح API أو بيانات النشر الخاصة.
- ضع القيم الحساسة في بيئة محمية أو إعدادات خادم.
- استخدم HTTPS للوصول الإنتاجي للوحة.
- حدّد وصول المشرف للموثوقين فقط.
- راجع روابط الاشتراك قبل نشرها علناً.

# 🧑‍💻 التطوير

للتجربة محلياً:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn main:app --host 0.0.0.0 --port 8080
```

ثم افتح:

```text
http://127.0.0.1:8080/white
```

للإنتاج أو الاشتراكات العامة استخدم اسم النطاق الحقيقي بدل `127.0.0.1` / `localhost`.
